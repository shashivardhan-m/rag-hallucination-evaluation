Title: Retrieval-Augmented Generation for Large Language Models: A Survey
Source: arXiv:2312.10997 (CC BY 4.0) — Excerpts for reproducible demo
Authors: Yunfan Gao et al.
---

ABSTRACT

Large Language Models (LLMs) demonstrate significant capabilities but face challenges such as hallucination, outdated knowledge, and non-transparent, untraceable reasoning processes. Retrieval-Augmented Generation (RAG) has emerged as a promising solution by incorporating knowledge from external databases. This enhances the accuracy and credibility of the generation, particularly for knowledge-intensive tasks, and allows for continuous knowledge updates and integration of domain-specific information.

RAG synergistically merges LLMs' intrinsic knowledge with the vast, dynamic repositories of external databases. This comprehensive review paper provides a detailed examination of the progression of RAG paradigms, encompassing the Naive RAG, the Advanced RAG, and the Modular RAG.

---

SECTION 1: INTRODUCTION

Large Language Models (LLMs) have demonstrated remarkable capability in generating text that is both coherent and contextually relevant. Models such as GPT-4, PaLM 2, and LLaMA 2 have shown strong performance across a wide range of natural language processing benchmarks. However, these models are not without limitations. A significant challenge is the phenomenon known as hallucination, where models generate factually incorrect information that appears plausible.

Hallucinations arise from the parametric nature of LLM knowledge storage. During pretraining, knowledge is compressed into the model weights, and this process inevitably introduces inaccuracies and incompleteness. Moreover, the static nature of pretraining data means that LLMs lack awareness of events occurring after their training cutoff.

Retrieval-Augmented Generation (RAG) addresses these limitations by augmenting LLMs with an external retrieval mechanism. At inference time, the system retrieves relevant documents from a knowledge base and conditions the generation on those documents. This grounds the model's output in verifiable external evidence.

---

SECTION 2: NAIVE RAG

The Naive RAG paradigm, also known as the basic RAG approach, was the first generation of RAG systems. It follows a straightforward "retrieve-then-read" pipeline.

Indexing Phase: Documents are segmented into smaller chunks. These chunks are then encoded into vector representations using a dense embedding model such as Dense Passage Retriever (DPR) or more modern alternatives like BAAI/bge-base-en-v1.5. The vectors are stored in a vector database such as FAISS, Pinecone, or Weaviate.

Retrieval Phase: Given a user query, the system computes the query embedding using the same encoder. It then retrieves the top-K most similar document chunks using approximate nearest neighbour (ANN) search, typically measured by cosine similarity.

Generation Phase: The retrieved chunks are concatenated with the original query and passed to an LLM as context. The LLM generates a response conditioned on this enriched prompt.

Limitations: Naive RAG suffers from several problems. Retrieval quality is not always aligned with generation quality. Irrelevant or noisy chunks can degrade the generated answer. Chunking strategies heavily influence downstream performance, and there is a significant sensitivity to chunk size and overlap parameters.

---

SECTION 3: ADVANCED RAG

Advanced RAG introduces additional mechanisms to improve upon Naive RAG. Key techniques include:

Pre-retrieval Optimisation: Query expansion, query rewriting, and hypothetical document embedding (HyDE). In HyDE, the model generates a hypothetical answer, encodes it, and uses it as the retrieval query.

Post-retrieval Processing: Reranking retrieved passages using a cross-encoder model (e.g., cross-encoder/ms-marco-MiniLM-L-6-v2). This allows finer-grained relevance scoring at the cost of additional computation.

Hybrid Retrieval: Combining dense semantic retrieval with sparse keyword retrieval (BM25). The scores are fused using Reciprocal Rank Fusion (RRF) or linear interpolation. Hybrid retrieval often outperforms either approach in isolation, especially for domain-specific queries.

SECTION 4: HALLUCINATION IN RAG SYSTEMS

Hallucination in RAG systems differs from standard LLM hallucination in important ways. Even with grounded retrieval, an LLM may:

1. Fail to faithfully use the retrieved context (context-grounded hallucination).
2. Generate claims that extrapolate beyond what the context states.
3. Produce answers that contradict retrieved evidence.

Faithfulness is the primary metric for evaluating RAG-specific hallucination. It measures whether each factual claim in the generated answer can be supported by the retrieved context. A common approach is to decompose the answer into atomic claims and use a Natural Language Inference (NLI) model to classify each claim as ENTAILMENT, NEUTRAL, or CONTRADICTION with respect to the context.

The faithfulness score is defined as: F = |Entailed Claims| / |Total Claims|

The hallucination rate is then 1 - F.

SECTION 5: EVALUATION METRICS

A comprehensive evaluation framework for RAG systems typically includes:

Reference-Free Metrics (do not require ground truth):
- Faithfulness: NLI-based claim verification against retrieved context
- Answer Relevance: Cosine similarity between answer embedding and question embedding
- Context Precision: Average similarity between question and retrieved chunks
- Context Recall (reference-free proxy): Average similarity between answer and retrieved chunks

Reference-Based Metrics (require ground truth answers):
- Answer Correctness: Composite of ROUGE-L and BERTScore against reference answer
- Context Recall (reference-based): Similarity between reference and retrieved context
- ROUGE-L F1: Longest common subsequence based recall/precision
- BERTScore F1: Contextualised token-level similarity using BERT embeddings

SECTION 6: CHUNKING STRATEGIES

Chunk size is one of the most critical hyperparameters in RAG systems. The optimal chunk size depends on:

1. The granularity of information in the source documents
2. The maximum context length of the LLM
3. The specificity of user queries

Small chunks (128-256 tokens) preserve localised, precise information but may lack sufficient context for generation. Large chunks (512-1024 tokens) provide more context but may dilute relevance scores and introduce noise.

Sentence-aware chunking, which splits at sentence boundaries to preserve semantic coherence, generally outperforms fixed-character splitting. Overlapping chunks (using a stride smaller than the chunk size) reduce the risk of relevant information being split across chunks.
